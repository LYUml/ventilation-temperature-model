# 基线温度方法总览与 Mac 交接

更新日期：2026-08-31

## 1. 研究目标

输入建筑 RDF、室外温度和可获得的房间温度，输出 2F、3F、4F 走廊未来 24 小时基线温度。本人的工作范围到此为止；TPE 参数标定、ELA 和 CONTAM 集成由师兄负责。

需要交给师兄的最终接口可概括为：

```text
RDF + 未来24小时温度输入 + 预测起点状态 -> 未来24小时走廊温度
```

当前首要判据：在相同、无泄漏的滚动 24 小时测试集上优于师兄原有的核滑动平均方法。

## 2. 当前数据

### 2.1 温度数据

文件：`data/TEMPERATURE-rev.csv`

- 时间范围：2026-05-09 00:00 至 2026-05-26 12:00。
- 共 421 个连续小时，无缺失、重复和非整小时间隔。
- 室外：`OUTDOOR`。
- 走廊：`2FCORRIDOR`、`3FCORRIDOR`、`4FCORRIDOR`。
- 房间：`2F215`、`3F308`、`3F309`、`3F310`、`4F408`、`4F409`、`4F410`、`4F411`、`5F510`。

已有同层房间温度可用于构造“房间均温－同层走廊温度”。早期 RC 模型已经用过这些房间温度，后续模型不能再忽略。

### 2.2 RDF

文件：`data/NBuilding.rdf`

包含空间、楼层、面积、体积、界面、内外边界、表面朝向、U 值、窗 SHGC 和可开启属性。当前走廊名义室外 UA 为：

| 楼层 | 外墙 UA | 窗 UA | 合计 UA |
|---|---:|---:|---:|
| 2F | 5.32 W/K | 27.20 W/K | 32.52 W/K |
| 3F | 5.32 W/K | 42.19 W/K | 47.51 W/K |
| 4F | 5.32 W/K | 40.78 W/K | 46.10 W/K |

注意：RDF 中“可开启”不代表监测期间真实开启；窗界面归属和有效参与面积仍需核验。

### 2.3 缺失数据

- 太阳辐射；
- 风速、风向；
- HVAC 启停、功率、送风温度或风量；
- 门窗实际开启状态；
- 人员/设备使用状态；
- 更长时间和其他季节的数据。

## 3. 统一评估口径

目前最可比的一组实验采用：

- 前 60% 训练；
- 中间 20% 验证和选参；
- 后 20% 锁定测试；
- 每个测试起点预测未来 24 小时；
- 每层 62 个重叠滚动窗口；
- 指标为三层 24 小时预测 RMSE 的算术平均。

需要注意：重叠窗口不是 62 组独立样本，因此不能把窗口数量直接当作统计独立样本量。

早期 `temperature_model.py`、`temperature_rc_model.py` 和 `validate_24h_baseline.py` 使用 70%/30% 切分，结果不能和 60%/20%/20% 表格直接横向排名。

## 4. 已尝试的全部基线温度方法

### 4.1 核滑动平均基线

脚本：`src/temperature_model.py`、`src/validate_24h_baseline.py`

原理：对室外温度作因果指数平滑，再对各层走廊做线性映射：

```text
S_t = alpha*S_(t-1) + (1-alpha)*T_out,t
T_corridor,f = intercept_f + slope_f*S_t
```

优点：稳定、参数少、无需未来走廊温度。缺点：物理解释有限，不能显式表达房间、围护结构和热容量。

在锁定 60/20/20 测试中的平均 RMSE 为 **0.343925 °C**，分层为：

| 2F | 3F | 4F |
|---:|---:|---:|
| 0.387949 | 0.256452 | 0.387374 |

这是当前必须超过的稳定基线。

### 4.2 一阶 RC 与邻室 RC

脚本：`src/temperature_rc_model.py`

基础形式：

```text
T_(t+1) = T_t + q + a*(T_out,t - T_t)
```

邻室形式：

```text
T_(t+1) = T_t + q + a*(T_out,t - T_t) + d*(T_room_mean,t - T_t)
```

邻室映射：2F 使用 `2F215`；3F 使用 `3F308/309/310` 均值；4F 使用 `4F408/409/410/411` 均值。

一步预测约为 0.15–0.21 °C，但使用了上一小时实测走廊温度，只能说明局部动力学拟合较好。连续 rollout 为 0.47–0.76 °C（邻室版）或 0.61–1.06 °C（基础版），不能用一步误差冒充 24 小时效果。

价值：已经证明同层房间温度具有信息量，下一版统一模型应继承这一边界项。

### 4.3 传统/机器学习批量基线

脚本：`src/benchmark_baseline_models.py`

全部使用相同的 60/20/20 锁定测试。排名如下：

| 排名 | 方法 | 平均 RMSE/°C |
|---:|---|---:|
| 1 | Kernel | 0.343925 |
| 2 | NARX-Ridge | 0.355049 |
| 3 | NARX-ExtraTrees | 0.394957 |
| 4 | Ridge distributed lag | 0.429427 |
| 5 | Direct MLP | 0.667899 |
| 6 | Kernel + MLP residual | 0.677661 |
| 7 | ExtraTrees | 0.736024 |
| 8 | 简化 2R2C | 0.782783 |
| 9 | HistGradientBoosting | 0.844082 |
| 10 | Gaussian Process | 0.887358 |
| 11 | NARX-MLP | 3.814326 |

结论：小数据下 Ridge 明显比 MLP 稳定；复杂非线性方法没有自然占优。

### 4.4 MLP + 紧凑 NSGA-II 搜索

脚本：`src/validate_mlp_nsga.py`

目标：直接输出三层未来 24 小时序列，同时优化验证误差和参数数量。选中结构为宽度 32、深度 2、学习率 0.01、无 weight decay，共 2808 个参数。

测试 RMSE：2F 0.855、3F 0.687、4F 0.816 °C，显著差于核基线。原因主要是 421 小时数据不足以支撑直接多输出 MLP，而非 NSGA 搜索力度不足。

结论：暂不继续扩大 MLP/NSGA 搜索。

### 4.5 混合与开源方法比较

脚本：`src/benchmark_hybrid_methods.py`

| 排名 | 方法 | 平均 RMSE/°C |
|---:|---|---:|
| 1 | Adaptive Kernel–RC–NARX Fusion | **0.279248** |
| 2 | Kernel | 0.343925 |
| 3 | Hierarchical RC–NARX–Ridge | 0.349559 |
| 4 | SysIdentPy polynomial NARX | 0.414465 |
| 5 | Grey-box RC structure search | 0.741949 |
| 6 | ORNL-style shared RC + floor delta | 0.757622 |

自适应融合形式：

```text
T_hat_f = w_f*T_kernel,f + (1-w_f)*(T_RC,f + RidgeResidual_f)
```

它是当前数值最优结果，比核基线提高约 18.9%。但概念上属于多个模型分工后再加权，不够“大一统”；而且会读取每个 24 小时窗口开始前一小时的实测走廊温度。可作为工程上限或对照，不宜直接包装成最终原创物理模型。

### 4.6 固定 Ceff 的物理正则化 NARX 状态空间模型

脚本：`src/validate_ceff_state_space.py`

设定 `Ceff = 165 kJ/(m²·K)`，走廊面积 53.58 m²，总热容量 8.8407 MJ/K；标定室外传热、隐含热质量耦合和 Ridge 正则热扰动。

平均 RMSE 为 **0.550775 °C**，差于核基线 60.1%。2F 和 4F 的室外传热系数被压到近 0，4F 的隐含热质量系数也近 0，说明参数互相替代、不可辨识。

对 `Ceff = 110/165/260 kJ/(m²·K)` 的扫描得到完全相同 RMSE，只是传热系数按比例缩放。这证明现有方程主要识别 `H/C`，不能从这些数据独立识别 H 和 C。

### 4.7 RDF 约束统一 2R2C

脚本：`src/validate_rdf_2r2c.py`；RDF提取：`src/rdf_building.py`

结构：

- 窗 UA 作为室外到室内空气的直接热路；
- 外墙 UA 拆成“室外—蓄热体—室内”的串联热路；
- Ceff 只允许在轻型 110 到重型 260 kJ/(m²·K) 之间变化；
- 加入受限渗透 UA 和周期热增益；
- 自动报告参数贴边。

平均 RMSE 为 **0.540773 °C**，分层为 0.487、0.438、0.697 °C，仍差于核基线 57.2%。

三层均出现：Ceff 达上限、空气等效热容量达上限、墙体阻力分配达边界、渗透接近 0。这说明模型在要求比 RDF 名义 UA 更慢的有效热响应；原始窗 UA 可能不能直接视为全部参与走廊热交换，且模型遗漏了邻室、太阳/HVAC 等边界。

## 5. 当前判断

1. 当前数值最优是自适应 Kernel–RC–NARX 融合，RMSE 0.279 °C，但统一性和解释性不足。
2. 当前最稳、最干净的部署基线仍是 Kernel，RMSE 0.344 °C。
3. 物理统一模型的主要问题不是优化器不够暴力，而是边界缺项和参数不可辨识。
4. `165 kJ/(m²·K)` 是中等热质量类别默认值，不是本楼实测或已标定值。
5. 已有房间温度此前被证明有用，应优先接入 RDF 约束 2R2C，而不是继续增加黑箱复杂度。

## 6. 下一步推荐路线

实现“房间–走廊耦合的 RDF 约束 2R2C”：

1. 用 RDF 邻接关系确定每层房间—走廊界面及名义 `UA_room-corridor`。
2. 将同层房间均温作为观测边界加入走廊能量平衡。
3. 4F额外测试 `5F510` 是否能代表上方热边界；必须标注它只是代理变量。
4. 室外围护结构 UA 使用带先验的有效参与倍率，不再完全锁死，也不允许自由降到 0。
5. Ceff 用标准值作为先验中心，报告 profile likelihood/多起点结果和参数边界。
6. 未测热增益只保留低维缓变状态，避免多组日周期、差分和残差项互相代偿。
7. 在相同 60/20/20、62 个滚动窗口下与 Kernel 0.343925 °C 比较。
8. 若仍贴边，再向师兄索取太阳辐射、HVAC、风和门窗状态；不要继续暴力扩大 MLP/NSGA。

建议同时保留两个产物：

- `stable_baseline`：核滑动平均，作为可靠交付兜底；
- `research_model`：房间–走廊耦合物理模型，只有在精度和参数合理性同时通过后才替代基线。

## 7. Mac 接手步骤

Windows 端提交并推送：

```powershell
git status

git push origin main
```

Mac 端：

```bash
git clone <repository-url>
cd ventilation-temperature-model/baseline-temperature
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python -m src.validate_24h_baseline --config configs/temperature_model.json
python -m src.validate_rdf_2r2c --config configs/temperature_model.json
```

`outputs/` 已被 Git 忽略，所以 Mac 上需要重新运行实验生成结果。这是预期行为；原始输入在 `data/`，配置在 `configs/`，结果不应进入版本库。
